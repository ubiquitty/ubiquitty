The license texts control, and each file's `SPDX-License-Identifier` header

## What Apache-2.0 allows

Apache-2.0 permits any use, including in commercial and competing products,
provided you keep the license and notices, mark modified files, and accept the
patent-termination condition. Embedding the engine in a paid IDE, shipping the
renderer in a closed-source app, running the host daemon on a fleet you
operate for customers, or writing a commercial Sync client all need nothing
beyond Apache-2.0's conditions. What it does not grant is the Ubiquitty name
and icon: a fork or a modified build must use its own.

## Why nothing is licensed more narrowly

The repository is the client, the daemon and the engine. Ubiquitty's
commercial side is an operated service, outside this repository, that
connects people to their hosts across networks and manages identity, sharing,
policy and audit. A narrower license on the daemon or the apps would not
protect that service; it would only make the daemon harder to package and
install on the machines the service exists to reach.

## The scope inventory

[The file-scope inventory](../license-scope.json) is the authoritative,
machine-checked form of this policy. Its boundary table assigns a license to
every first-party path (one Apache-2.0 entry for the repository, plus the MIT
and CC-BY-4.0 exceptions); its rules record files that cannot carry a header,
generated data that combines Apache-2.0 with a data license, and upstream
material with its own terms. `Scripts/check-licenses.py` fails any header that
disagrees with its entry, any first-party path no entry claims, and any
upstream file whose declared license was replaced.

### Placing a new file

A new original file takes `SPDX-License-Identifier: Apache-2.0`. A file that
cannot carry a header, or that carries third-party material, gets a rule in
the inventory with its reason and the notice it preserves.

## Third-party code, generated data, and notices

Third-party components retain their own licenses, as listed in
[third-party-notices.md](../third-party-notices.md). The macOS app, the iOS
app, and UbiquittyKit.framework each carry the complete notice set in their
resources, checked after every build, so every font they bundle travels with
its license. Generated Unicode tables,
Unifont and proportional font data, and the built-in theme data carry
identifiers that combine Apache-2.0 for the wrapper code with the applicable
data licenses. Their generators are Apache-2.0; that does not change the
generated data's terms.

The PGO profiles under `Support/pgo/` are generated by `Scripts/pgo-train.sh`
from instrumented runs of the repository's benchmarks over the code compiled
into Core, its vendored libraries included; a profile holds function names and
execution counts, and no source text or data. They are Apache-2.0.

[The file-scope inventory](../license-scope.json) also records the terms of
files that cannot carry a header, such as fonts, binary fixtures, and JSON,
and identifies the notices for upstream material. `Scripts/check-licenses.py`
checks every repository path against it. Missing, conflicting, or unclassified
identifiers fail the check. An unresolved provenance finding is reported
explicitly and blocks the release check; a matching identifier alone is not
proof of the right to redistribute a file. The Apache-2.0 text is pinned by
digest, so an edited copy fails the check; it is the unmodified copy served by
the Apache Software Foundation.
