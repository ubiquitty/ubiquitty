# core-srcs-excluded.txt — portable-Core sources the live-Terminal tests skip.
#
# run-tests.sh's CORE_SRCS array is the subset of the portable Core
# (Scripts/portable-core-sources.txt, the SSOT that CMake and the wasm build
# read) needed to instantiate and drive a headless Ubiquitty::Terminal in a unit
# test: the parser, the screen, VT/OSC/DCS handling, image decode. It leaves out
# the renderers, the session and input layers, themes, config, the command
# palette, and the mux protocol — a headless Terminal never reaches those.
#
# Every source in the SSOT belongs to exactly one of CORE_SRCS or this file.
# check-core-srcs-complete.py enforces the partition, so a Core source added to
# the SSOT forces a decision — into CORE_SRCS if the live Terminal needs it, here
# if it does not — rather than a silent undefined-symbol link break. That break
# takes every CORE_SRCS stanza down at once: a handler registered in
# Dispatch.cpp whose source stays out of CORE_SRCS is a call nothing in the link
# defines, and nothing here runs the whole suite to notice.
#
# Grouped by subsystem for reading only; the gate ignores comments and blanks and
# reads this as a flat set. Keep entries as paths relative to the repo root.
# --- Source/Core/App ---
# App-level theme/appearance/config-reload policy over a host seam the frontend
# implements. A headless Terminal reaches none of it, and its own test builds it
# directly.
# The first-launch Welcome screen and the shell-integration installer edit one of its
# buttons makes. Content and a file transform, over no live Terminal; each has
# its own test.
# --- Source/Core/Rendering ---
# --- Source/Core/Security ---
# --- Source/Core/Session ---
# --- Source/Core/Input ---
# --- Source/Core/Protocol ---
# The Sync wire: a peer's codec and connection state, which no headless Terminal reaches.
# --- Source/Core/Themes ---
# The theme list and a theme's colours as bytes, for a frontend's picker. A
# headless Terminal is never themed.
# --- Source/Core/Preferences ---
# The key-addressed read and write. No headless Terminal test reaches it: a
# settings surface is what asks by key, and the suite drives the accessors.
# The fold from preferences to a renderer's configuration. A headless
# Terminal is never rendered from it.
# The per-range font overrides, written back to the file. A settings surface
# writes one; a headless Terminal reads routing already parsed into Values.
# --- Source/Core/Clipboard ---
# Typed clipboard staging is exercised by its dedicated test target; the basic
# Terminal harness supplies its own clipboard client.
# The clipboard shims read their own argv; a headless Terminal never runs one.
# Workspace adapters have dedicated targets with transport and session support.
# The basic Terminal dependency set does not construct either adapter.
# --- Source/Core/CommandPalette ---
# --- Source/Core/Screen ---
# --- Source/Platform ---
# --- Source/Core/Runtime ---
# The drain pass and the coherence rule serve a host that drains a PTY and
# publishes frames; a stanza parsing bytes into a headless Terminal does neither.
# The tmux control host drives a session's hosted windows; a headless Terminal
# hosts none, and its own test links the whole Core.
